# corpus/no_comments_pdf_was_generated_by_word

A copy of the benchmark corpus where every `.docx` has had **Word comments
stripped** and every `.pdf` was rendered directly by **Microsoft Word**
(via AppleScript `save as … file format format PDF`, with the GUI "Best
for printing" sticky preference set).

The sibling directory `corpus/word_based/` holds the originals — same
file names, but the `.docx` files still carry comments and the PDFs were
rendered by LibreOffice. Files that share a name between the two directories
are **not** byte-identical.

---

## What "comments stripped" means

Every `.docx` here was passed through jubarte's
`MarkupSimplifier.SimplifyMarkup({ RemoveComments: true })`, which:

1. Deletes the `word/comments.xml` part from the OOXML package.
2. Strips `w:commentRangeStart`, `w:commentRangeEnd`, `w:commentReference`,
   and `w:annotationRef` elements from the document body.
3. Drops `w:rStyle w:val="CommentReference"` runs.

Comment removal isolates tracked-change fidelity in downstream redline
comparison — comments are orthogonal metadata that some engines choke on or
alter. Even documents with zero comments produce a different byte stream
because the simplifier re-serializes the entire package (canonicalized XML,
changed ZIP metadata).

## What "PDF generated by Word" means

Every `.pdf` here was exported by Microsoft Word on macOS through a
monolithic AppleScript (`tell application "Microsoft Word" → save as theDoc
file name "…" file format format PDF`). The "Best for printing" export
quality was pinned by manually exporting one PDF in the Word GUI first
(Word reuses the last-chosen quality as a sticky preference). These are
**not** LibreOffice renders.

## Directory guide

### Source documents

| Directory | Contents |
|---|---|
| `docx_source/` | Base `.docx` documents (comments stripped). The canonical input fed to every redline tool. 199 files. |
| `docx_source_randomized/` | Same 199 documents renamed to `file_N.docx` in randomized order, for blind A/B testing. |
| `pdf_source/` | Each `docx_source/*.docx` exported to PDF by Word. |

### Word oracle redlines (ground truth)

| Directory | Contents |
|---|---|
| `docx_redlines_word/` | Microsoft Word's own document-compare output — the canonical tracked-change `.docx` for each `base → next` pair. |
| `pdf_redlines_word/` | Each `docx_redlines_word/*.docx` exported to PDF by Word. These are the **pixel-scoring oracle**. |
| `docx_accepted_word/` | Word redlines with all tracked changes accepted (for the `accepted_changes` benchmark). |
| `pdf_accepted_word/` | Each `docx_accepted_word/*.docx` exported to PDF by Word. |

### Randomized corpus

| Directory | Contents |
|---|---|
| `docx_redlines_randomized/` | Word-generated redlines for the randomized `file_N → file_M` pairs. |
| `pdf_redlines_randomized/pdf/` | Those redlines exported to PDF by Word. |
| `pdf_source_randomized/` | Randomized source DOCX exported to PDF by Word. |

### Manifest

| File | Purpose |
|---|---|
| `centralized_mapping.csv` | Authoritative pairing table (`pair_stem`, `base`, `next`, `origin`, paths, `missing`). |
| `centralized_mapping_randomized.csv` | Same schema, keyed to the randomized `file_N.docx` naming. |

### Artifacts (not used by scoring)

| Directory | Contents |
|---|---|
| `word_captures_superdoc_style/` | Per-document Word screen captures and repair-dialog evidence from earlier SuperDoc fidelity debugging. |
| `word_working_roundtrip/` | Intermediate DOCX files from Word open → edit → save roundtrip experiments. |
